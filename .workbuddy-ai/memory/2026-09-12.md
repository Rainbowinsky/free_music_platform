## 项目结构分析（QQ音乐 Web 复刻版）

对 `E:\Code\ds\music` 做了完整结构梳理，结论要点：

- **定位**：QQ音乐 Web 复刻（React18+TS+Vite5+react-router6+zustand）+ 独立曲库管理后端（Express5+MySQL8）。
- **代码规模**：src/server/scripts 合计约 12,968 行（含 CSS）。
- **前端**：`App.tsx` 按路由分流；`/admin*` 走独立布局（AdminConsole，1244 行，含 import/upload/library/users 四个 tab），主站走 TopBar+Sidebar+PlayerBar 布局。10 个页面路由。
- **状态层**：zustand 6 个 store —— auth / ui / theme / library / player / catalog。
- **播放器**：`src/store/player.ts` 用单例 `HTMLAudioElement`，核心难点是 seek 爆音抑制（fadeVolume 45ms 淡出→seeked→90ms 淡入，beginScrub/endScrub 拖动时暂停定位）。
- **数据源双轨**：主站账号/歌单/喜欢/最近播放走 localStorage（`src/lib/db.ts`）；曲库走 `src/store/catalog.ts` 拉 `/api/library/songs`，失败回退 `src/data/songs.ts` 静态 20 首。
- **后端**：`server/src/index.js` 入口 → routes/library.js（公开读）+ routes/admin.js（JWT+admin 角色）；music/ 下四个模块 sources/normalize/agent/importer。
- **检索入库流水线**（核心亮点）：规则拆分查询（口语化才调模型）→ 多源召回（网易云官方 + meting 中转）→ 方向纠正（"歌手 歌名"自动换向）→ 候选打分 → 源级熔断探测音频体积 → 两阶段返回（/search 先返回规则结果，/judge 异步补模型裁决）。可取消：searchId + AbortController 贯穿。
- **音源实测结论**：只有 netease 能下全曲；kugou/tencent 仅用于发现条目补元数据，标 `audioAvailable=false`、置信度封顶 35、不可入库。
- **去重与归一化**：`normalize.js` 的 titleKey/artistKey（繁简异体字表 VARIANT）、artistMatches（互相包含）、MODIFIER 正则识别非原版、scoreCandidate 打分。
- **媒体存储**：public/{music,covers,lyrics} 共 35 组，music 346MB / covers 44MB；MySQL 只存元数据+相对路径（src/cover/lrc）。
- **表结构**：users / artists / albums / songs（ON DUPLICATE KEY 以 source+source_id 幂等）/ import_tasks。

**注意**：`server/.env.local` 存在，内含 DB 口令与 DEEPSEEK_API_KEY，已在 .gitignore 中，分享代码时勿泄漏。

## 代码审计（安全与问题排查）

排查了全项目，确认的问题清单（按严重度）：

**严重 / 中危**
1. `src/lib/db.ts` — 主站密码**明文存 localStorage**（`password: string` 直接写入 `qqmusic.db.v1`），登录做 `record.password !== password` 明文比对。任何 XSS 或同源脚本可读走全部账号口令。
2. `/api/admin/cover` 无鉴权且是**开放代理**：`COVER_HOST_ALLOW` 允许 `*.qijieya.cn` 整个域（第三方中转域，非可信图床），服务端会带 UA/Referer 去 fetch，返回体只校验 `content-type: image/*`，无体积上限 → 可被用于打满内存/磁盘带宽。`/api/admin/*` 里唯一不要求 adminRequired 的路由（因 `<img src>` 无法带请求头）。
3. 全站**无限流**：`/api/auth/login` 可无限暴力破解（bcrypt 10 rounds 只拖慢单次）；`/api/admin/search` 每次触发外部模型与音源请求，登录态下可被刷成本。
4. `app.use(cors())` **无 origin 白名单**，配合 Vite 代理同源，跨域配置过于宽松。
5. `JWT_SECRET` 默认值硬编码 `qqmusic-dev-secret-please-change`，未配置即用弱密钥签发，可伪造任意管理员 token。
6. 默认管理员 `admin/admin123456` 在有数据前自动创建，登录页 placeholder 还直接提示了这个口令。

**逻辑缺陷**
7. `server/src/routes/library.js:143` 更新专辑用 `WHERE name = ?`，而 `admin.js:488` 用 `WHERE name_key = ?`。`name_key` 是 `titleKey()` 归一化（去括注/标点/小写），所以用户输入带标点或括注时**永远匹配不到**，album 静默不更新（无报错）。两处实现不一致。
8. `src/store/catalog.ts` 降级到静态曲库时**静默**：`error` 字段存了原因但 `useCatalogSource` 全项目无人使用（只有定义），用户看到 20 首静态歌却不知道后端挂了、管理台新歌全部消失。
9. `dist/` 是**陈旧构建**（17:51），源码已更新到 19:59；实测 dist 里搜不到「曲库管理台」「搜歌入库」「adminApi」任何字符串 → dist 里根本没有管理台。生产部署会少一大块功能。

**低危 / 健壮性**
10. `server/src/index.js:32` `express.static(PROJECT_ROOT/public)` 挂的是 public，暂时安全，但若哪天改成挂 PROJECT_ROOT 就会暴露 `server/.env.local`（DB 口令 + DeepSeek Key）。建议收窄到 media 三个目录。
11. 无序归一化：`library.js:127` 与 `admin.js:472` 各自内联了一份标题归一化正则，与 `normalize.js` 的 `titleKey()` 重复且不一致（前者用 `.toLowerCase()` 不做 stripBrackets）。
12. `uploads` 的 multer 无 `fileFilter`，仅前端 `accept="audio/*,..."` 限制（可绕过）；后端不校验 mimetype，任意 60MB 文件都会落到 public/music 并解析。
13. `judgedCache` 用 `Map` + `delete(map.keys().next().value)` 做 LRU 淘汰，不是真正的 LRU（只是插序淘汰），并发搜索下可能淘汰掉正在用的候选。

**验证方式**：`/api/library/*` 确认公开无鉴权（只有 PATCH 加 adminRequired）；`app.listen(config.port)` 未指定监听 host，默认监听全部网卡。

**需求**：账号管理页要能看到全部用户并管理；新建 `root` 用户并授予超管权限，该权限可给任何人授予/撤销管理员权限。用户确认的权限边界："可管理管理员，但自身不可被降级"。

## 改造：「我的音乐」私有数据迁到后端（彻底解决换设备丢数据）

**背景**：喜欢/收藏/歌单/最近播放原本存在 localStorage 的 `qqmusic.db.v1`（按 username 隔离），换浏览器或清缓存就丢。用户要求彻底解决。

**新增 4 张表**（`server/src/db.js`，均对 `users` 有 `ON DELETE CASCADE`）：
- `user_songs(user_id, song_id, kind ENUM('like','recent'), uk_user_song_kind)` —— 喜欢与最近播放共用一张表，靠 kind 区分
- `user_playlists(user_id, title, description, cover, created_at, updated_at)`
- `user_playlist_songs(playlist_id, song_id, added_at)`
- `user_collected_playlists(user_id, playlist_id)`

**关键设计决定**：`song_id` 存**前端 `Song.id`**（网易云 sourceId 字符串，如 "1357375696"），不是 `songs` 表自增主键；**刻意不加 `songs` 外键**——否则管理台删歌会连带清掉用户数据，且静态兜底曲库里的歌可能还没入库。

**后端** `server/src/routes/me.js`（新增，`router.use(authRequired)`）：`GET /library` 一次返回全部；`POST /likes/:songId`、`POST /collected/:playlistId` 切换；`POST|DELETE /recent`（后者的裁剪用 delete-then-insert + keep-100 子查询）；`POST|PATCH|DELETE /playlists[/:id]`；`POST|DELETE /playlists/:id/songs[/:songId]`。**越权防护**靠 `ownPlaylist(userId, rawId)`——所有歌单写操作先校验归属，改别人的歌单返回 404（不是 403，避免泄漏歌单是否存在）。

**前端**：
- `src/lib/db.ts` — 新增 `MeError` + `meApi`（10 个方法，薄封装 `/api/me/*`，含 `toPlaylist()` 做字段还原）；删掉已死的 `getLibrary`/`saveLibrary`。
- `src/store/library.ts` — **整体重写**为后端驱动 + 乐观更新：写操作先改内存再发请求，失败回滚并写入 `error` 字段；`loadFor` 变 async（期间切账号会丢弃过期结果）；`createPlaylist`/`addSongToPlaylist` 变 async 返回 Promise。**未登录时**：最近播放仍走 `store.saveGuestRecent`，其余只改内存不落盘。
- `src/store/migrate.ts`（新增）— 一次性迁移旧 localStorage 数据到后端。**保守策略**：只补后端还为空的部分（后端已有喜欢就不推喜欢），同一个账号只迁移一次（`qqmusic.migrated.v1` 记录），失败不标记以便重试。
- `src/components/SyncBanner.tsx`（新增）+ `App.tsx` 挂载 —— 同步失败不再静默，带"重试"按钮。
- 各调用点适配 async：`PlaylistModal`（加 busy 态）、`AddToPlaylistModal`（加 busyId 态）、`PlaylistDetail`、`Recent`、`Collection`、`player.ts`（`void` 掉不阻塞播放）、`useRequireLogin`（统一 `Promise.resolve` 接住，避免 unhandled rejection）、`SongList`/`PlaylistCard` 的 `onRemove` 签名放宽为 `void | Promise<void>`。
- 文案：Likes/Collection 的"保存在本地浏览器"→"已同步到账号"。

**踩到的坑（重要）**：迁移时**喜欢/收藏的插入顺序也需要 reverse**。旧数组是"最近在前"，后端按 `created_at DESC` 展示，顺序插入会导致顺序整个反过来（实测 `[a1,a2]` 变成 `[a2,a1]`）。最近播放我一开始就 reverse 了，但喜欢/收藏漏了——第一次模拟验证时发现并修掉。

## 搜歌入库多源方案评估（仅分析，未改代码）

- 当前检索已是网易云官方接口 + Meting 多源召回；`netease` 是唯一会自动下载音频的来源，`kugou/tencent` 仅用于发现候选。无可用音源时已支持仅元数据建档与 QQ 音乐搜索外链；本地文件上传还能解析 ID3 并用网易云补专辑、封面和歌词。
- 建议保留“音频可入库”与“元数据可入库”两条独立路径：对受版权保护的商业歌曲不做跨平台自动下载；仅允许用户上传其有权使用的本地音频或跳转官方平台。
- 后续如需多源，应建立适配器能力分层和授权门禁：MusicBrainz + Cover Art Archive 用于权威元数据/封面，Jamendo 等仅在 API 明确 `audiodownload_allowed=true` 且许可证符合用途时下载；Internet Archive 仅纳入可核验的公版或兼容 CC 条目。持久化许可证、署名、来源页与校验信息，以便审计和后续下架。

## 本地上传归档方案（仅分析与文档，未改业务代码）

- 当前本地上传入口只接受一个 `file` 字段（前端只处理第一个文件），选择器提示 MP3/FLAC/M4A/WAV/OGG；后端以 60MB `multer.memoryStorage` 接收，读取内嵌标签和封面，再以网易云搜索补专辑、封面、歌词。
- 关键阻断缺陷：所有上传音频的原始字节都会被固定写成 `.mp3` 文件名；FLAC/M4A/WAV/OGG 会发生内容、扩展名与 MIME 不一致，导致浏览器播放不可靠。解析失败也未阻断，仍可能标为可播放。
- 当前不支持自带 `.lrc` 或独立封面文件、批量专辑、上传预览确认、为现有仅元数据歌曲补媒体；在线补全仅依赖网易云。
- 已新增交付文档 `docs/本地上传完整归档方案.md`：说明支持范围、完整归档资源要求、P0/P1/P2 问题清单、目标数据模型与四阶段改造路径。建议先修真实格式保存/转码与媒体校验，再加多字段上传和“补齐现有条目”。

## 修复：歌词抽屉展开/收回时顶部白色渐变突兀 + 主页面模糊过渡

**问题**：歌词抽屉（`.lyrics-view`）滑动展开/收回时，上边缘会突然出现/消失一圈白色渐变。根因是 `.lyrics-bg`（封面模糊背景层）的 `inset: -90px` + `blur(72px)` + `scale(1.18)` 会溢出抽屉上边缘约 90px 的模糊亮斑，滑动过程中露在主页面顶部。

**改动**：
1. `src/styles/lyrics.css` — `.lyrics-view` 加 `overflow: hidden` 裁掉溢出亮斑（负 inset 保留，抽屉内部模糊边缘仍正常）。
2. `src/App.tsx` — 新增 `.app-shell` 包裹 TopBar + app-body（顶栏+内容区）；播放条、队列抽屉、歌词页、各弹窗都在 shell 外，不受 filter 影响。已确认 shell 内无 `position: fixed` 后代（fixed 元素全是 shell 外的兄弟节点），filter 产生的新包含块无副作用。
3. `src/components/LyricsView.tsx` — 原有 `no-scroll` 的 effect 里同步切换 body 的 `lyrics-open` class。
4. `src/styles/lyrics.css` — `.app-shell` 加 `transition: filter 0.42s cubic-bezier(0.22,0.61,0.36,1)`（与抽屉缓动严格一致）；`body.lyrics-open .app-shell` 应用 `filter: blur(16px) brightness(0.72)`；`prefers-reduced-motion` 下关闭该过渡。效果：抽屉上滑时主页面同步模糊+压暗，抽屉下滑时反向还原——类 iOS 通知中心。

**验证**：`tsc --noEmit` 通过；`vite build` 通过（285.05 kB）。dev server（5199 端口）HMR 已生效。

## 修复：歌手列表页封面全部不显示（渐变占位）

**现象**：歌手列表页 22 位歌手里只有 2 位显示真封面，其余全是「渐变圆 + 姓氏首字」；点进歌手详情页却有图。

**根因**：数据源字段不同。
- 列表页（`src/pages/Artists.tsx`）用 `/api/library/artists` 的 `artists.cover` 列 → 实测 22 位里 **20 位为空**；
- 详情页（`src/pages/ArtistDetail.tsx:48`）用 `songs[0].cover`（歌曲封面）→ 有值。
- `Cover.tsx` 在 `src` 为空时退化为渐变占位（这是设计行为），所以表现为"列表没图、详情有图"。

**为什么 `artists.cover` 会空**：`importer.js` 里歌手头像是可选的，只在「导入该歌手第一条带封面的歌」时才回填一次，首条无图就永远空着。反证：唯一有图的两位分别是独立上传过头像的（周杰伦 `manual-*`）和首条恰好带图的（松原みき）。`songs.cover` 其实**全部有值且文件 200 可访问**，封面文件本身没问题。

**修复（3 处）**：
1. `server/src/routes/library.js` — `/artists` 的 SQL 把 `ar.cover` 改为 `COALESCE(NULLIF(ar.cover, ''), MAX(s.cover))`，歌手无独立头像时回退到该歌手任一歌曲封面。**不需数据迁移**，且与详情页展示口径一致。
2. `server/src/music/importer.js` — 回填条件从 `!artistRow.cover`（依赖 findOrCreateArtist 的快照）改为 SQL 侧判空 `UPDATE artists SET cover = ? WHERE id = ? AND (cover IS NULL OR cover = '')`，防止未来新入库歌手重现同类问题，同时仍不覆盖已有的独立头像。
3. `src/pages/Artists.tsx` — 接口判断从 `data?.items?.length` 放宽为 `data?.items`，避免曲库为空时整体回落到内置静态数据。

**验证**：重启后端后实测 `/api/library/artists` → `total 22, empty_cover 0`，逐张探测 22 个封面 URL 全部 200（22/22）。`tsc --noEmit` 通过，`importer.js` 可正常 import。

**注意**：本次改的是后端路由与 SQL，**必须重启 `npm run server` 才生效**（前端 HMR 不会重载后端）。
